# Hermes 自动文本提取协议

## 触发条件

用户输入 **"开始获取文本任务"** → 自动执行本流程。不需要额外描述。

## 自主性要求（铁律）

> ⚠️ **整个会话只有这一条用户消息，之后不会有任何后续输入。**

- **禁止等待用户确认、澄清或补充信息**
- 所有决策必须自主完成：引擎判断、加密方式、解密策略、字段筛选、输出格式
- 遇到问题时：换思路、换工具、换路径，**绝不中断等待用户**
- 充分利用已有 skill 中的**方法论和思路**，但**绝不照搬具体答案**（见下方"反路径依赖"）

## 反路径依赖（核心原则）

> ⚠️ **每个 APK 都是全新的逆向工程问题。上一个游戏的有效解法，对下一个游戏大多数情况下是无效的。**

- Skill 中记录的密钥（如 `dtou4guxiang`）、签名（如 `libai`）、DELTA 值等，是**历史案例的参考**，证明"这类加密存在且可解"
- **禁止**未经分析就直接套用历史密钥/算法。必须先检查当前 APK 的文件头、加密特征、SO 库结构
- 正确的使用方式：看到加密特征 → 回忆"之前用 IDA xref 找到了 XXTEA key" → 对**当前** SO 执行相同分析流程 → 得出**当前**的 key
- 错误的使用方式：看到 .luac → 直接拿 `dtou4guxiang` 解密 → 发现不行 → 卡住

## 禁止暴力字符串提取

> ⚠️ **严禁通过二进制扫描（strings / grep 可读字符串）直接提取文本作为最终结果。**

- 从 .so / .luac / 加密文件中直接 `strings` 扫出的中文碎片**不是游戏原文**，是无意义的
- 文本必须经过正确的解密/反编译流程后，从**结构化数据**（配表字段、Translate 表、StringConstants 等）中提取
- `strings` 命令只能用于**辅助定位**（如找密钥字符串、函数名），不能作为提取手段

## 设计约定

- **每次调用 = 全新的独立会话**，无上下文污染
- **apks/ 目录保证只有 0 或 1 个 APK**，由上游调用方保证
- 工作流只认**一个** APK，找到就处理，没有就报空

## 边界情况

| 条件 | stdout 输出 | outputs/ 行为 |
|------|-------------|---------------|
| apks/ 为空 | `"目前没有任务"` | 不写入 |
| 处理成功 | `"全部任务已完成"` | **移入**最终 CSV |
| **超时（≥1 小时）** | stdout 报告超时 | **移入** `"解密失败"` 的 CSV |
| 解密失败 | 报错信息 | **移入** `"解密失败"` 的 CSV |
| 其他异常 | 报错信息 | 不移入任何文件 |

## 执行时间限制

- **硬上限：1 小时（3600 秒）**
- 外部调用方用 `subprocess.run(timeout=3600)` 控制
- **超时后 Hermes 进程会被直接杀死，无法自行写 CSV**
- 因此：**"解密失败" 的 CSV 由外部调用方负责写入**

### 努力程度要求

> ⚠️ **用尽全部办法，尽量在 1 小时内获取。不可轻易放弃。**

遇到困难时的应对策略（按优先级）：
- IDA 反编译失败 → 换反汇编、读 ARM 指令、手动推导算法
- 自定义加密 → 逐字节分析加密流程、跟踪寄存器变化、尝试常见变体（标准 XXTEA/AES/XOR/zlib 组合）
- 无符号表 → 通过字符串 xref、调用图、已知函数签名定位关键函数
- 密钥动态生成 → 分析密钥派生机制的每步操作
- 全目录无中文字符 → 扩大搜索范围（Unicode 扩展区、编码转换、压缩层）
- 单一方法无效 → 立即切换思路，尝试其他 skill 中记录的模式

**放弃条件**：只有当所有合理的技术路径都已尝试且确认无效时，才可写入"解密失败"并结束。**严禁**因"看起来很难"、"IDA 报错"、"没找到明显特征"等初步困难就提前终止。

## 目录约定

- APK 输入: `{{HERMES_ROOT}}\apks\`
- 工作区: `{{HERMES_ROOT}}\`
- 交付区: `{{HERMES_ROOT}}\outputs\`

## 工作流程

1. 扫描 `apks/` → 0个输出"目前没有任务"，1个进入处理
2. 解包: `work_dir = {{HERMES_ROOT}}\work_{jobid}`
3. 引擎识别 → 定位文本来源
4. IDA 分析 so，找解密逻辑
5. 提取文本 → 写入 CSV（末尾追加 `__SESSION_ID__: {session_id}`）
6. 移入 `outputs/` → 输出 "全部任务已完成"
